# v0.3.1 Credibility Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align public validation claims with repository evidence and add bounded CI checks for float32 and newest allowed dependencies before v0.3.1.

**Architecture:** Keep physics, released task behavior and public Python APIs unchanged. Add durable metadata contract tests for public claims, expose the existing validation parametrization to a float32-only pytest process, and add one weekly unlocked dependency job beside the reproducible locked matrix.

**Tech Stack:** Markdown, JSON, pytest, JAX, GitHub Actions, uv, GitHub branch protection.

**Spec:** GitHub issue #6, `https://github.com/beomdo-park/QEnvS/issues/6`

## Global Constraints

- Do not change physics, released task behavior or public Python APIs.
- Use plain ASCII punctuation as required by `AGENTS.md`.
- Use no GPU. Keep local pytest serial or at four workers or fewer.
- Do not run the complete local test suite. Run touched tests locally and leave the full matrix to GitHub CI.
- Keep locked CI for reproducibility. The unlocked dependency check is an additional weekly and manual job.
- Make every public claim traceable to a check, commit or explicit limitation.

## Review Focus

- A reader must not infer that every model has a QuTiP cross-check when the qubit validation module does not.
- Round 6 must distinguish repository-backed findings from private mutation-run counts that cannot be reconstructed.
- `QENVS_TEST_X64=0` must leave JAX x64 disabled before validation modules create arrays.
- The float32 CI job must run every registered physics check serially without enabling x64 through the CLI.
- The newest-dependency job must resolve beyond `uv.lock` without changing the committed lockfile.
