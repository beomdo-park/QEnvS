# QEnvS 0.3 plan (2026-10-15)

Goal: the next roadmap items, released more carefully than 0.1 and 0.2. Every phase has a
gate; nothing ships that does not pass it, and the final 0.3.0 tag waits for the
maintainer's explicit GO after a release candidate.

## What changed in the facts

* **JOSS eligibility.** JOSS now expects at least six months of public development
  history before submission, with releases, public issues or pull requests, and commits
  spread over that period; projects whose history is concentrated in a few weeks can be
  desk-rejected. The repository became public on 2026-10-13, so the earliest submission
  is about 2027-04-13. The paper is therefore deferred: draft in 2027-03 from the then
  current state, and use public issues and releases in the meantime.
* **A stability-policy breach in 0.2.0.** `griffe.find_breaking_changes` against v0.1.0
  shows that `qenvs.toolkit.UNITS` was removed without a deprecation period, contrary to
  `docs/stability.md`. 0.3 restores it as a deprecated alias, and an API gate in CI makes
  this kind of slip impossible to repeat silently.

## Phases and gates

| phase | deliverable | gate (must pass before the next phase) |
|---|---|---|
| A. Release safety rails | API gate (griffe diff against the last release tag, explicit allowlist for intended changes); golden snapshot of every released task (defaults, spaces, reference-policy return, zero-policy return, a fixed random-pulse return); `RELEASING.md`; `toolkit.UNITS` restored with a `DeprecationWarning` | CI fails on an unlisted breaking change and on any change of a released task's behaviour; snapshot covers all six 0.2 tasks |
| B. Pulse I/O | `qenvs.pulses`: a `Pulse` record (samples, sample period, channel names, units, provenance), JSON / NPZ round trip, exact resampling of piecewise-constant pulses to a hardware sample period (for example 2/9 ns), conversion between rad/ns and MHz; `Transmon.from_properties` reading frequency, anharmonicity, T1, T2 from a plain dict with explicit units | round trips are exact; a resampled pulse gives the same propagator to 1e-12 (x64); unit conversions checked against hand values; 1 adversarial review |
| C. Two-qubit cross-resonance | two coupled transmons (Duffing, exchange coupling J, common frame at the drive frequency, CR drive on the control and a cancellation drive on the target); `qenvs.gates` gains a `subspace` argument (backward compatible) for the computational states of two qutrits; task `transmon/CRGate-v0` with target ZX(pi/2) in the qubit frames | closed forms: J = 0 decoupling, single-qubit limits, static ZZ at second order, ZX rate against the perturbative formula at weak drive (reference verified before citing), QuTiP cross-check, CPTP, solver convergence; 2 adversarial reviews (physics, mutation) |
| D. Dicke with local dissipation | new model and task `battery/DickeLocal-v0` (the released `battery/Dicke-v0` is untouched): permutation-invariant Liouvillian over all spin sectors (method of Shammah et al. 2018) for local emission, dephasing and pumping, coupled to the cavity | agreement with a brute-force 2^N Hilbert-space simulation for N <= 4 to 1e-8 (x64); collective-only limit equals `battery/Dicke-v0`; QuTiP PIQS cross-check where available; if the brute-force gate fails, D moves to 0.4 and 0.3 ships without it; 2 adversarial reviews |
| E. Release candidate | tag `v0.3.0rc1` (a PyPI pre-release: `pip install --pre qenvs==0.3.0rc1`) | full CI matrix, API gate, golden snapshot, strict docs, fresh-install dry run of the tutorial and `qenvs validate`, review log updated, changelog with migration notes |
| F. 0.3.0 | final tag | maintainer GO after looking at the release candidate; any fix after rc1 means rc2 |

Out of 0.3: the JOSS paper (2027-03, see above), GPU benchmarks, virtual-Z optimisation,
readout.

## Order and cost

A is done by the lead (no agents). B, C and D run as one pipeline: three implementers and
five reviewers (B 1, C 2, D 2), at most six in flight, sonnet for review and for B, the
session model for the physics of C and D. Expected agents: about 8, plus up to 3 fixers.

## Decisions taken here

* New physics goes into new task ids; released tasks never change (`-vN` rule).
* `gates.average_gate_fidelity` keeps its current signature; `subspace` is a new keyword
  with the old behaviour as default.
* D is the riskiest item and is allowed to slip to 0.4 instead of delaying 0.3.
