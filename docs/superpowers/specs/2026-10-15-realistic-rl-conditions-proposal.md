# 기획안 v3: QEnvS 0.3 "현실적인 RL 조건" (불확실성 아래 강건성 평가)

작성 2026-10-15, v2와 v3 같은 날. 2차 검토 판정: 조건부 승인, 아래 수정 후 구현 착수. 외부 검토용으로, 이 문서만 읽어도 판단할 수 있도록 배경부터
적었습니다.

## 0. v1 대비 변경 (1차 검토 반영)

| 검토 지적 | v2 반영 |
|---|---|
| 매개변수 오차, 제어 오차, 측정 잡음은 물리적으로 다른 현상인데 한 래퍼에 섞임 | 세 계층으로 분리: `ParameterRandomization`(에피소드 고정 모델 매개변수), `ControlErrors`(에피소드 고정 보정 오차와 스텝별 제어 잡음), 관측 모드와 `shots`(측정). 난수도 계층별 독립 스트림 |
| 난수 키 분할과 재현성, 배치 위치 독립성을 별도로 검증해야 함 | 키 구조를 명시(4.1)하고 게이트 G2를 세분화 |
| 진폭 오차 공식의 가정(sigma의 의미, 상대 오차, 게이트 대 상태 충실도, 근사 범위)이 모호 | 근사식 대신 가정을 고정한 정확식 사용(6.G4). 게이트 충실도와 상태 충실도, 정규와 균등 분포를 각각 따로 검증 |
| 샷 잡음 분산 p(1−p)/n은 이진 결과에만 성립 | 관측량마다 고유기저에서 측정하는 정확한 유한 샷 모델(다항분포)로 교체, 이상값과 추정값을 분리해 제공 |
| CVaR 정의(성능 대 손실), 표본 수, 학습과 평가 분포 분리 | 정의와 추정량, 평가 키 분리, 표본 수 안정성 검사를 명시(4.5) |
| `reveal=True`는 oracle 설정임을 명시 | `oracle=True`로 이름을 바꾸고 같은 평가 분포에서 블라인드와 비교 |
| `strength`가 모든 분포를 같은 비율로 키우면 단위와 지지집합 문제가 생김 | 매개변수별 기준 분포와 단위, 지지집합을 명시하고 `strength`는 폭만 조절, 지지집합을 벗어나면 생성 시 오류 |
| strength=0 비트 동일성은 측정 잡음이 켜져 있으면 성립하지 않음 | 게이트 G1의 조건을 "측정 잡음과 스텝별 제어 잡음이 꺼져 있을 때"로 한정 |

## 0b. v2 대비 변경 (2차 검토 반영, 구현 착수 조건)

| 검토 지적 | v3 반영 |
|---|---|
| 스텝별 잡음 공식 s/sqrt(H)는 일반 펄스에 성립하지 않음 | 일정 진폭 펄스를 H개의 같은 스텝으로 나눈 경우로 한정해 검증. 일반 궤적에는 공식을 주장하지 않음(6.G4) |
| 균등분포 식의 a = 0 | 극한값 0으로 처리(6.G4) |
| "서로 다른 키는 서로 다른 표본" 테스트는 잘못된 요구 | 제거. 결정론적 재현성, 배치 위치 독립성, 계층 간 설정 독립성, 표본 분포와 상관 특성을 각각 검증(6.G2). 에피소드 키 생성 규칙 고정(4.1) |
| 정확한 기댓값을 `info`에 넣으면 학습 경로로 새어 나갈 수 있음 | 기본 `info`에는 정책이 받는 값만. 정확값은 `diagnostics=True`일 때만 `info["diagnostics"]`에, 또는 `env.diagnostics(state)`로(4.4) |
| 샷 비용, 에르미트 조건 | 스텝당 총 샷 = shots x 관측량 수를 문서화하고 `info["shots_used"]`로 보고. 비에르미트 관측량은 생성 시 거부(4.4) |
| 게이트 태스크의 `state` 관측 의미 | 전파자(닫힌계) 또는 초연산자(개방계)를 반환함을 문서와 `env.observation_kind`로 명시(4.4) |
| 채널 간 제어 오차 상관 | 기본은 채널별 독립, `correlated=True`면 모든 채널에 같은 값(공통 AWG 이득). 자르기 비율을 `info["clip_fraction"]`로 보고(4.3) |
| 최솟값과 부트스트랩, 변동성 구분 | 최솟값은 표본 수에 민감한 기술 통계로만. 구간은 평균과 CVaR에만. 학습 시드 간 변동과 평가 표본 변동을 따로 보고(4.5) |
| oracle 정규화가 strength = 0에서 0으로 나눔 | 기본 분포의 기준 폭으로 정규화, 기준 폭이 0인 매개변수는 oracle 관측에서 제외(4.2) |
| 사용자 정의 모델 계약 | 모델 공통 계약 `parameter_specs()`(단위, 지지집합, 기준 폭), `with_parameters(**values)`(순수 함수), `check_parameters()`를 정의. 내장 모델 구현, `HamiltonianModel`은 H = H0 + sum_k p_k O_k 형태의 매개변수 항으로 지원(4.2) |

## 1. 배경

QEnvS(`pip install qenvs`)는 양자 제어 문제를 RL과 최적 제어에 쓸 수 있게 만든 오픈소스
라이브러리입니다. 핵심 가치는 "물리적으로 검증된 환경"입니다. 모든 모델은 해석해, 물리
제약, 솔버 수렴, QuTiP 교차검증으로 이루어진 검증 체크(현재 67개)를 통과해야 들어갈 수
있고, 체크는 float32와 float64 양쪽에서 돌아갑니다.

- 구조: `Model`(해밀토니안, 제어 연산자, Lindblad 점프 연산자) → 함수형 `Environment`
  (`reset(key)`, `step(state, action)`, JAX의 jit, vmap, grad 지원) → Gymnasium 어댑터와
  벡터 환경 → 레지스트리(`qenvs.make("transmon/XGate-v0")`)
- 현재 태스크: 큐비트 상태 전이, 큐비트 배터리, Dicke 배터리(N셀과 공진기), Lambda STIRAP,
  트랜스몬 X와 SX 게이트(ns, GHz 단위, 누설 포함). 0.3에서 2큐비트 cross-resonance,
  Dicke 국소 산일, 펄스 입출력을 추가하는 중입니다.
- 버전 0.2.0(2026-10-15). 0.3은 신중하게 내기로 해서 API 게이트(griffe로 직전 릴리스 대비
  호환성 파괴 검사), 릴리스된 태스크의 동작 스냅샷 테스트, 릴리스 후보(rc) 절차를 먼저
  만들었습니다. 규칙: 릴리스된 태스크의 동작은 바꾸지 않고, 바꿀 때는 `-vN`을 올립니다.

## 2. 문제

현재 환경은 실험실과 두 가지 점에서 다릅니다.

1. **매개변수가 매번 정확히 같다.** 실제 장비는 보정 사이에 주파수와 진폭이 드리프트하고,
   모델과 장비가 어긋납니다. 강건 제어가 필요한 이유이지만, QEnvS에서는 이를 학습할
   방법이 없습니다.
2. **에이전트가 양자 상태 전체를 본다.** 관측이 상태 벡터(또는 밀도행렬)를 펼친 것이라,
   실험에서는 불가능한 정보입니다. 실제로는 측정으로 얻은 기댓값만, 그것도 유한한 샷
   수에 따른 잡음과 함께 얻습니다.

근거:
- 큐비트 주파수를 에피소드마다 ±0.1% 흔들어 RL을 학습하면 보정 사이 드리프트에 강해지지만
  최저 오류는 다소 높아진다는 보고(arXiv:2511.07076, 2025).
- 모델 불일치를 RL 잔차 보정으로 줄이는 연구(Jaouadi, Ashhab, 2026, arXiv:2604.19990),
  드리프트 강건 RL 게이트의 실험(Niu 외, PRX Quantum 2021).
- Dicke 배터리 RL에서 관측 조건 4가지를 비교해, 부분 관측은 성능이 떨어지고 2차 상관을
  더하면 전체 상태 대비 94~98%를 회복한다는 결과(arXiv:2511.12176).
- 다단계(커리큘럼) RL로 잡음을 단계적으로 키워 배터리를 강건하게 충전하는 연구
  (AAAI 2026 student abstract).
- 이런 설정을 표준화한 벤치마크는 찾지 못했습니다.

## 3. 목표와 비목표

목표
- 어떤 태스크(사용자 정의 모델 포함)에도 씌울 수 있는 매개변수 무작위화와 강건성 평가.
- 실험에서 얻을 수 있는 정보만 쓰는 관측 모드와 샷 잡음.
- 기존 태스크의 기본 동작은 그대로(스냅샷 테스트 통과).

비목표(이번 범위 밖)
- 소산율(T1, T2, kappa 등) 무작위화: 현재 코드에서 이 값들이 닫힌계와 개방계 분기, 상태
  종류(ket과 밀도행렬)를 정하므로, 흔들려면 별도 설계가 필요합니다.
- 측정 역작용(붕괴), 확률 주 방정식(SME), 단일 샷 판독.
- 비마르코프 저장소.

## 4. 설계: 세 계층으로 분리한 불확실성

### 4.1 무작위성의 세 종류와 난수 구조

| 계층 | 물리 현상 | 언제 뽑나 | 난수 스트림 |
|---|---|---|---|
| 모델 매개변수 | 공진 주파수, 비조화성, 결합 세기 등의 장비별 편차와 보정 사이 드리프트 | 에피소드 시작 시 한 번, 에피소드 내 고정 | `fold_in(episode_key, 0)` |
| 제어 오차 | 진폭 보정 오차(에피소드 고정)와 펄스마다의 제어 잡음(스텝별) | 보정 오차는 리셋 시, 잡음은 매 스텝 | `fold_in(episode_key, 1)`, 스텝 k는 `fold_in(그 키, k)` |
| 측정 | 유한 샷 추정의 통계적 변동, 양자 상태는 바꾸지 않음 | 매 관측 | `fold_in(episode_key, 2)`, 스텝 k는 `fold_in(그 키, k)` |

- 에피소드의 결과는 그 에피소드의 key에만 의존합니다. 배치에서의 위치, 다른 에피소드, 다른
  계층의 설정과 무관합니다. 예를 들어 `shots`를 바꿔도 뽑히는 모델 매개변수는 같습니다.
- `fold_in`으로 스트림과 스텝을 유도하므로 스텝을 몇 번 진행했는지에 따라 키가 결정되고,
  재시작과 병렬 실행에서 순서 의존성이 없습니다.
- 상태에는 공칭 `EnvState`에 더해 표본 매개변수와 에피소드 key를 담는 불변 구조를 씁니다
  (래퍼 전용 상태 클래스). 기존 `EnvState`는 바꾸지 않습니다.
- 에피소드 키 생성 규칙(고정): 실행 key 하나에서 i번째 에피소드의 key는
  `fold_in(run_key, i)`입니다. 벡터 환경과 `qenvs.robust.evaluate`가 이 규칙을 따르므로, 실행
  key와 에피소드 번호만 알면 어떤 에피소드든 다시 만들 수 있습니다.
- 보장하는 성질과 검증 방법을 구분합니다. 결정론적 재현성(같은 key와 설정이면 비트 단위로 같음)과
  계층 간 분리(한 계층의 설정을 바꿔도 다른 계층의 key와 표본이 같음)는 테스트로 직접
  확인합니다. 통계적 독립성은 key가 다르다는 사실로 보장되는 것이 아니므로, 표본 분포와 상관
  검사로 확인합니다(6.G2).

### 4.2 모델 매개변수 무작위화: `ParameterRandomization`

```python
from qenvs.wrappers import ParameterRandomization, Normal, Uniform

renv = ParameterRandomization(
    qenvs.make("transmon/XGate-v0"),
    {
        "anharmonicity_ghz": Normal(std=0.005, unit="GHz"),     # 공칭값 주변
        "detuning_ghz": Uniform(half_width=0.002, unit="GHz"),
    },
    strength=1.0,      # 각 분포의 폭(std 또는 half_width)에 곱하는 배율
    oracle=False,      # True: 표본 매개변수를 관측에 붙임(oracle 설정)
)
```

- 분포는 공칭값을 중심으로 한 오프셋입니다. `Normal(std)`, `Uniform(half_width)`,
  `TruncatedNormal(std, low, high)`를 지원합니다. 모델마다 매개변수의 단위와 물리적 지지집합을
  선언하고(예: 트랜스몬 비조화성은 음수, 결합 세기는 양수), `strength`를 곱한 분포가
  지지집합을 벗어날 수 있으면 생성 시점에 오류를 내 절단 분포를 쓰게 합니다.
- 모델 공통 계약(사용자 정의 모델 포함):
  - `parameter_specs()`: 무작위화할 수 있는 매개변수마다 단위, 물리적 지지집합, 기준 폭을 돌려줌.
  - `with_parameters(**values)`: 값을 바꾼 새 모델을 돌려주는 순수 함수(jit과 vmap 안에서 동작).
  - `check_parameters(**values)`: 적용 전후의 불변조건 검사(예: 해밀토니안 에르미트성, 지지집합).
  내장 모델은 해밀토니안 매개변수(디튜닝, 비조화성, 결합 세기, omega0 등)를 선언합니다. 구조
  매개변수(`levels`, `n_cells`)와 소산율은 선언하지 않으며, 지정하면 이유와 함께 오류입니다.
- `HamiltonianModel`(사용자 정의 모델)은 이름 붙은 매개변수가 없으므로, 매개변수 항으로
  지원합니다: `from_operators(..., parameters={"J": (nominal, operator, unit, support, width)})`이면
  drift = H0 + sum_k p_k O_k 이고, p_k가 무작위화 대상입니다. 연산자가 에르미트인지는 생성 시
  검사합니다.
- `oracle=True`는 정책에 실제 표본값을 알려 주는 설정이며, 실제 장비에서는 그 값을 별도
  보정으로 추정해야 한다는 점을 문서에 적습니다. 관측에는 단위 없는 정규화 값을 붙이는데,
  분모는 `strength`와 무관한 기본 분포의 기준 폭입니다(strength = 0에서도 0으로 나누지 않음).
  기준 폭이 0인 매개변수는 oracle 관측에서 뺍니다. 표본은 에피소드 내 고정이므로, `"state"` 관측 모드에서
  oracle 관측을 붙이면 관측이 다시 Markov 상태가 됩니다. 블라인드 설정이나 부분 관측 모드에서는
  매개변수나 상태의 일부를 모르는 부분 관측(POMDP) 문제입니다.

### 4.3 제어 오차: `ControlErrors`

```python
from qenvs.wrappers import ControlErrors

cenv = ControlErrors(env, amplitude_scale=Normal(std=0.02), step_noise=Normal(std=0.01))
```

- `amplitude_scale`: 상대 진폭 보정 오차, 에피소드 고정. 실제 진폭 = 명령 진폭 x (1 + epsilon).
- `amplitude_offset`: 채널별 절대 오프셋(rad/ns 등 태스크 단위), 에피소드 고정.
- `step_noise`: 스텝마다 독립인 상대 잡음.
- 적용 순서: 명령 진폭에 보정 오차, 오프셋, 잡음을 순서대로 적용한 뒤 한계로 자릅니다
  (`action_bound`). 이것은 명시적으로 정의한 시뮬레이션 모델이며, 모든 장비의 실제 오차 발생
  순서를 대표한다고 주장하지 않습니다.
- 채널 간 상관: 기본은 채널마다 독립 표본, `correlated=True`면 모든 채널에 같은 값(예: 공통 AWG
  이득 오차).
- 잡음 뒤 자르기는 분포를 경계에 쌓이게 하므로, 스텝마다 잘린 채널의 비율을
  `info["clip_fraction"]`로 보고하고 벤치마크 문서에 함께 적습니다.

### 4.4 측정: 관측 모드와 `shots`

| 모드 | 관측 | 비고 |
|---|---|---|
| `"state"` | 상태를 펼친 것과 시간 비율 | 기본값, 지금과 동일. 이상적 전체 관측 |
| `"expectations"` | 모델 관측량의 기댓값과 시간 비율 | 부분 관측 |
| `"correlations"` | 위에 2차 상관 관측량(모델이 정의) | 부분 관측 보강 |
| `"time"` | 시간 비율만 | 개루프(블라인드) 제어 |

- `shots=None`(기본)이면 시뮬레이터가 계산한 정확한 기댓값을 그대로 줍니다. 이것은 측정
  잡음이 없는 이상값입니다.
- `shots=n`이면 관측량마다 그 고유기저에서 n번 측정한 결과로 추정합니다. 관측량 O의 고유값
  lambda_j와 확률 p_j = Tr(P_j rho)로 결과 횟수를 다항분포에서 뽑고(조건부 이항분포의 연쇄로
  정확히 구현), 추정값은 결과 고유값의 표본 평균입니다. 분산은 정확히
  (⟨O²⟩ − ⟨O⟩²)/n이고, 사영 연산자는 이항분포 p(1−p)/n의 특수한 경우입니다. 관측량마다 별도
  실험으로 측정한다고 가정하므로, 서로 교환하지 않는 관측량도 문제없습니다.
- 정보 경계: 정책이 받는 관측과 `info`의 기본 내용은 설정한 관측 모드와 샷 모델을 따르는 값뿐입니다.
  정확한 기댓값은 진단용이며 `diagnostics=True`를 켰을 때만 `info["diagnostics"]`에 들어가고, 함수형
  API에서는 `env.diagnostics(state)`로 따로 얻습니다. oracle 매개변수는 `oracle=True`일 때만
  관측에 들어갑니다.
- 샷 예산: 관측량이 K개면 스텝당 총 측정 횟수는 shots x K입니다. `shots=1000`은 관측량당
  1000샷이라는 뜻이며, 스텝당 총 샷을 `info["shots_used"]`로 보고합니다.
- 관측량은 에르미트 연산자여야 하며(결과가 실수 고유값), 비에르미트 연산자는 생성 시 거부합니다.
  복소 상관량이 필요하면 실수부와 허수부를 각각 에르미트 관측량으로 정의합니다.
- 범위: 관측은 양자 상태를 바꾸지 않습니다(측정 역작용 없음). 결과는 "이상적인 상태 진화에
  잡음 있는 관측을 결합한 제어"이며, 측정 결과로 상태가 붕괴하는 폐루프 피드백은 아닙니다.
  관측량당 n샷은 매 스텝 별도 실험을 반복하는 비용이라는 점도 적습니다.
- 게이트 태스크에서 `"state"`는 단일 상태가 아니라 누적 전파자(닫힌계) 또는 초연산자(개방계)를
  반환합니다. 실험적으로는 공정 단층촬영에 해당하는 이상적 정보이며, 환경의 `observation_kind`
  속성("state", "propagator", "superoperator")과 문서로 구분합니다. 게이트 태스크는 이것과
  `"expectations"`(초기 상태를 진화시킨 상태의 관측량)만 지원합니다.

### 4.5 강건성 평가: `qenvs.robust.evaluate`

- 성능 지표는 태스크의 반환값(예: 게이트 충실도 증가분, 저장 에너지)입니다. 높을수록 좋습니다.
- 보고: 평균, 최솟값, 하위 10% CVaR(성능 분포 하위 10%의 평균). 구간(부트스트랩 95%)은 평균과
  CVaR에만 붙입니다. 최솟값은 표본 수가 늘수록 낮아지는 기술 통계로만 보고하고, 표본 수가 다른
  최솟값끼리 비교하지 않습니다. CVaR 추정량은 n개 표본을 정렬해 하위 ceil(0.1 n)개의 평균이며,
  성능 기준 정의라 손실 기준 CVaR와 꼬리 방향이 반대라는 점을 문서에 적습니다.
- 학습과 평가 분리: `evaluate`는 명시적 평가 key를 요구하고, 평가 분포를 따로 받을 수 있습니다.
  학습에 쓴 key 스트림과 겹치지 않도록 문서와 예제에서 분리합니다.
- 기본 평가 표본 수 1024, 그리고 256, 1024, 4096에서 지표가 안정적인지 보고합니다. 무작위화가
  없는 공칭 환경에서의 성능도 함께 보고해, 강건성을 얻느라 공칭 성능을 잃었는지 보이게 합니다.
- 학습 결과 비교는 여러 독립 학습 시드로 하고, 학습 시드 간 변동(정책마다 다름)과 평가 표본
  변동(분포에서 다시 뽑을 때)을 하나의 구간으로 합치지 않고 따로 보고합니다.

## 5. 호환성

- 새 래퍼와 kwargs(`observation`, `shots`)는 추가뿐이고, 기본값은 지금 동작과 같으므로 릴리스된
  태스크 id는 그대로 둡니다(스냅샷 테스트로 확인). 공개 API는 추가만 합니다(API 게이트).
- 기존 `EnvState`와 `step`은 바꾸지 않습니다. 스텝별 난수는 래퍼와 관측 계층에서 `fold_in`으로
  유도하므로 기존 태스크의 key 처리도 그대로입니다.

## 6. 검증 게이트 (통과 못 하면 해당 항목은 0.3에서 제외)

- **G1 기본 동작 보존**: 측정 잡음과 스텝별 제어 잡음이 꺼져 있고 모든 폭이 0이면, 래퍼를 씌운
  환경의 전이, 보상, 관측이 원래 환경과 x64에서 비트 단위로 같다(모든 태스크).
- **G2 재현성과 분리, 통계적 성질**: 같은 key와 설정이면 비트 단위로 같은 결과; 단일 실행과
  1024개 배치 실행에서 같은 에피소드 key의 결과가 같다(배치 위치 독립); 한 계층의 설정을 바꿔도
  다른 계층의 key와 표본이 같다; 에피소드 키 규칙 `fold_in(run_key, i)`로 임의의 에피소드를
  재생성할 수 있다; 서로 다른 에피소드의 표본은 분포 검사(평균, 분산)와 상관 검사를 통과한다.
  "서로 다른 key는 서로 다른 값"은 요구하지 않는다.
- **G3 물리 제약**: 뽑힌 매개변수가 선언된 지지집합 안에 있고, 표본마다 해밀토니안이
  에르미트이며, 지지집합을 벗어날 수 있는 설정은 생성 시 거부된다.
- **G4 해석 검증(가정 고정 후 비교)**: 가정은 상대 진폭 오차 epsilon, 평균 0, 에피소드 고정,
  2준위 극한의 닫힌 공진 pi 펄스(제어 진폭 x 시간 = pi)입니다. 회전각 pi(1 + epsilon)에서
  게이트 불충실도는 1 − F_avg = (2/3) sin²(pi epsilon / 2), 상태 불충실도(|0>에서 |1>)는
  sin²(pi epsilon / 2)입니다. 기댓값은 근사 없이
  - 정규 N(0, sigma²), sigma는 표준편차: E[1 − F_avg] = (1/3)(1 − exp(−pi² sigma² / 2)),
    E[1 − F_state] = (1/2)(1 − exp(−pi² sigma² / 2))
  - 균등 U(−a, a), a는 반폭(표준편차 a/sqrt(3)): E[1 − F_avg] = (1/3)(1 − sin(pi a)/(pi a)),
    a = 0에서는 극한값 0
  - 스텝별 잡음은 적용 범위를 한정합니다: 일정 진폭 pi 펄스를 H개의 같은 스텝으로 나누고(스텝마다
    회전각 pi/H), 각 스텝에 독립 상대 잡음(표준편차 s)만 있을 때, 회전 축이 같으므로 회전각 오차는
    pi 곱하기 평균 잡음이고 표준편차는 s/sqrt(H)입니다. 이 경우에만 위 정규 공식에 sigma 대신
    s/sqrt(H)를 넣어 검증하고, 진폭이 스텝마다 다른 일반 궤적에는 이 공식을 주장하지 않습니다.
  시뮬레이터(`transmon/XGate-v0`의 `levels=2`와 `qubit/StateTransfer-v0`)로 4096개 표본의
  평균을 내고, 표본 표준오차의 4배 이내로 일치해야 합니다. 이 식들은 몬테카를로로 미리
  확인했습니다(sigma = 0.01, 0.05, 0.2와 a = 0.02, 0.1, 0.3에서 상대 오차 0.1% 이내).
  통계 게이트는 테스트마다 고정한 key를 쓰므로 결과가 결정론적이고(재실행해도 같은 판정), 허용
  기준은 구현 전에 이 문서에 고정합니다. 통계 검사 전체(약 10개)의 우연한 실패 확률은 4 sigma
  기준에서 10^-3 수준입니다. 통계 게이트에 앞서 결정론적 기준값(epsilon을 하나로 고정했을 때의
  닫힌 형식 값, 1e-10 이내)을 먼저 확인합니다.
- **G5 측정 통계**: 10^4번 반복에서 추정값의 평균이 정확한 기댓값과 표준오차 4배 이내,
  분산이 (⟨O²⟩ − ⟨O⟩²)/n과 상대 5% 이내. 사영 연산자(점유율)와 고유값이 여러 개인 관측량
  (예: Dicke 배터리 에너지) 모두. `shots=None`이면 정확값과 같고, 관측은 양자 상태를 바꾸지
  않으며, 스텝마다 잡음이 독립. 비에르미트 관측량은 거부되고, `diagnostics=False`(기본)에서는
  정확값이 관측과 `info` 어디에도 없으며, `info["shots_used"]`가 shots x 관측량 수와 같다.
- **G6 강건성 평가**: 알려진 분포(예: 성능이 균등분포인 경우)에서 CVaR 추정량과 그 구간이 정확값을
  포함; 평가 key를 주지 않으면 오류; 256, 1024, 4096 표본에서 평균과 CVaR의 변화 보고(최솟값은
  기술 통계로만).
- **G3b 모델 계약**: 모든 내장 모델과 매개변수 항을 쓴 `HamiltonianModel`에서 `with_parameters`가
  jit과 vmap 안에서 동작하고, `check_parameters`가 지지집합 밖의 값과 비에르미트 결과를 거부한다.
- **G7 배치 실행**: 1024개 에피소드에서 표본이 서로 독립이고(상관 검사), 시간과 메모리 사용을
  측정해 문서에 기록.

## 7. 시연 (게이트 아님, 결과를 있는 그대로 공개)

- Dicke 배터리 N=4에서 PPO를 관측 조건 3가지(`state`, `expectations`, `expectations`와 1000샷)로
  3시드씩 학습하고, 별도 평가 key로 평가.
- 트랜스몬 X 게이트에서 공칭 GRAPE와 강건 GRAPE(학습 표본 K개 평균 최적화)를 진폭 오차 분포
  위에서 평균, 최솟값, CVaR로 비교(평가 표본은 학습 표본과 분리).
- 같은 평가 분포에서 블라인드 정책과 oracle 정책 비교.

## 8. 범위 밖과 향후 설계 메모

- 소산율 무작위화: 현재 소산율이 0인지 아닌지가 닫힌계와 개방계 경로, 상태 종류(ket과
  밀도행렬)를 정합니다. 무작위화하려면 "항상 개방계 경로" 옵션(rate 0도 점프 연산자로 포함)이
  필요하고, 이것은 기존 태스크의 경로를 바꾸므로 새 태스크 id나 옵션으로 설계해야 합니다.
- 구조 매개변수(`levels`, `n_cells`, Fock 컷오프): 배열 크기가 바뀌므로 jit과 vmap 안에서
  무작위화할 수 없습니다. 크기별로 따로 컴파일하는 방식이 필요합니다.
- 측정 역작용, 확률 주 방정식, 단일 샷 판독, 측정 기반 피드백: dynamiqs의 SME 솔버를 이용한
  별도 기능으로 계획합니다.

## 9. 핵심 기여 (문서와 릴리스 노트의 표현)

1. 재현 가능한 물리 매개변수 무작위화: 명시적 난수 구조, 에피소드 고정 표본, 배치 실행.
2. 관측 불확실성의 분리: 이상적 상태와 기댓값, 유한 샷 추정을 구별해 제공.
3. 분포 기반 강건성 평가: 학습에 쓰지 않은 매개변수 분포에서 평균과 하위 꼬리 성능 검증.

## 10. 일정과 비용

0.3 계획의 단계 B2로, 진행 중인 단계 B, C, D 이후 rc1 전에 넣습니다. 구현 2개(무작위화와 제어
오차, 관측과 측정 통계), 적대검증 2개(물리와 통계, API와 변이 테스트)로 에이전트 약 4개,
수정에 1~2개를 더 씁니다. 게이트를 못 넘는 항목은 0.4로 미루고 0.3 일정은 늘리지 않습니다.

## 11. 위험

- 매 스텝 `eqx.tree_at`으로 모델을 바꾸는 비용: 처리량 저하를 측정해 문서에 적습니다.
- 고유분해가 필요한 관측량의 측정 모델: 고유분해는 모델 생성 시 한 번만 하고, 축퇴 고유값은
  같은 결과로 묶습니다.
- 기댓값 관측이 실험적으로 얼마나 비싼지(관측량당 n샷, 매 스텝)는 사용자 판단 몫이며 문서에
  명시합니다.

## 12. 상태

2차 검토에서 조건부 승인을 받았고, 위 수정(0b)을 반영해 구현 착수 조건을 충족했습니다. 남은
결정은 없습니다. G1~G7과 G3b를 순서대로 진행하며, 게이트를 통과하지 못한 기능은 성능과 무관하게
0.3에 넣지 않고 0.4로 넘깁니다.
