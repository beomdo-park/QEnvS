## 0b. 3차 검토 반영

## 1. 배경

QEnvS(`pip install qenvs`)는 양자 제어 문제를 RL과 최적 제어에 쓸 수 있게 만든 오픈소스 라이브러리입니다. 핵심 가치는 "물리적으로 검증된 환경"입니다. 모든 모델은 해석해, 물리 제약, 솔버 수렴, QuTiP 교차검증으로 이루어진 검증 체크(현재 67개)를 통과해야 들어갈 수 있고, 체크는 float32와 float64 양쪽에서 돌아갑니다.

- 구조: `Model`(해밀토니안, 제어 연산자, Lindblad 점프 연산자) → 함수형 `Environment`(`reset(key)`, `step(state, action)`, JAX의 jit, vmap, grad 지원) → Gymnasium 어댑터와 벡터 환경 → 레지스트리(`qenvs.make("transmon/XGate-v0")`)
- 현재 태스크: 큐비트 상태 전이, 큐비트 배터리, Dicke 배터리(N셀과 공진기), Lambda STIRAP, 트랜스몬 X와 SX 게이트(ns, GHz 단위, 누설 포함). 0.3에서 2큐비트 cross-resonance, Dicke 국소 산일, 펄스 입출력을 추가하는 중입니다.
- 버전 0.2.0(2026-10-15). 0.3은 신중하게 내기로 해서 API 게이트(griffe로 직전 릴리스 대비 호환성 파괴 검사), 릴리스된 태스크의 동작 스냅샷 테스트, 릴리스 후보(rc) 절차를 먼저 만들었습니다. 규칙: 릴리스된 태스크의 동작은 바꾸지 않고, 바꿀 때는 `-vN`을 올립니다.

## 2. 문제

현재 환경은 실험실과 두 가지 점에서 다릅니다.

1. **매개변수가 매번 정확히 같다.** 실제 장비는 보정 사이에 주파수와 진폭이 드리프트하고, 모델과 장비가 어긋납니다. 강건 제어가 필요한 이유이지만, QEnvS에서는 이를 학습할 방법이 없습니다.
2. **에이전트가 양자 상태 전체를 본다.** 관측이 상태 벡터(또는 밀도행렬)를 펼친 것이라, 실험에서는 불가능한 정보입니다. 실제로는 측정으로 얻은 기댓값만, 그것도 유한한 샷 수에 따른 잡음과 함께 얻습니다.

근거:
- 큐비트 주파수를 에피소드마다 ±0.1% 흔들어 RL을 학습하면 보정 사이 드리프트에 강해지지만 최저 오류는 다소 높아진다는 보고(arXiv:2511.07076, 2025).
- 모델 불일치를 RL 잔차 보정으로 줄이는 연구(Jaouadi, Ashhab, 2026, arXiv:2604.19990), 드리프트 강건 RL 게이트의 실험(Niu 외, PRX Quantum 2021).
- Dicke 배터리 RL에서 관측 조건 4가지를 비교해, 부분 관측은 성능이 떨어지고 2차 상관을 더하면 전체 상태 대비 94~98%를 회복한다는 결과(arXiv:2511.12176).
- 다단계(커리큘럼) RL로 잡음을 단계적으로 키워 배터리를 강건하게 충전하는 연구(AAAI 2026 student abstract).
- 이런 설정을 표준화한 벤치마크는 찾지 못했습니다.

## 3. 목표와 비목표

목표
- 어떤 태스크(사용자 정의 모델 포함)에도 씌울 수 있는 매개변수 무작위화와 강건성 평가.
- 실험에서 얻을 수 있는 종류의 정보(관측량 기댓값의 유한 샷 추정)만 쓰는 관측 모드. 측정 역작용과 판독 오류 같은 하드웨어 측정 과정 자체는 모델링하지 않음(보상은 예외, 4.4).
- 기존 태스크의 기본 동작은 그대로(스냅샷 테스트 통과).

비목표(이번 범위 밖)
- 소산율(T1, T2, kappa 등) 무작위화: 현재 코드에서 이 값들이 닫힌계와 개방계 분기, 상태 종류(ket과 밀도행렬)를 정하므로, 흔들려면 별도 설계가 필요합니다.
- 측정 역작용(붕괴), 확률 주 방정식(SME), 단일 샷 판독.
- 보상의 측정 추정(유한 샷 보상).
- 비마르코프 저장소.

## 4. 설계: 세 계층으로 분리한 불확실성

### 4.1 무작위성의 세 종류와 난수 구조

| 계층 | 물리 현상 | 언제 뽑나 |
|---|---|---|
| 모델 매개변수 | 공진 주파수, 비조화성, 결합 세기 등의 장비별 편차와 보정 사이 드리프트 | 에피소드 시작 시 한 번, 에피소드 내 고정 |
| 제어 오차 | 진폭 보정 오차(에피소드 고정)와 펄스마다의 제어 잡음(스텝별) | 보정 오차는 리셋 시, 잡음은 매 스텝 |
| 측정 | 유한 샷 추정의 통계적 변동, 양자 상태는 바꾸지 않음 | 매 관측 |

난수 트리(잎 단위로 고정):

```text
run_key
└── episode_key[i] = fold_in(run_key, i)
    ├── 0 매개변수                   fold_in(episode_key, 0)
    │   └── 매개변수 이름별          fold_in(., crc32(name))
    ├── 1 제어 오차                  fold_in(episode_key, 1)
    │   ├── 0 보정(에피소드 고정)    fold_in(., 0)
    │   │   ├── 0 배율 오차          fold_in(., 0)
    │   │   └── 1 오프셋             fold_in(., 1)
    │   └── 1 스텝 잡음              fold_in(., 1)
    │       └── 스텝 k               fold_in(., k)
    ├── 2 측정                       fold_in(episode_key, 2)
    │   └── 관측 시점 t              fold_in(., t)   (t = 0은 reset 직후, t = k는 k번째 step 후)
    │       └── 관측량 j             fold_in(., j)
    └── 3 정책 표본(평가 전용)       fold_in(episode_key, 3)
        └── 시점 t                   fold_in(., t)   (t는 행동을 고르는 시점, 0부터)
```

- 계약: 한 잎의 사용(뽑는 개수, 분포, 켜고 끔)을 바꿔도 다른 잎의 표본은 바뀌지 않습니다. 예를 들어 `shots`나 스텝 잡음을 바꿔도 모델 매개변수 표본은 같고, 보정 오차를 꺼도 스텝 잡음은 같습니다.
- 확률적 정책은 시점마다 다른 키 `fold_in(fold_in(episode_key, 3), t)`를 받으므로, 한 에피소드 안에서 같은 난수 표본이 재사용되지 않고 에피소드 재현성은 유지됩니다. 이 잎은 `qenvs.robust.evaluate`가 정책을 돌릴 때만 쓰며, Gymnasium 경로의 학습에서는 RL 라이브러리가 자기 난수를 관리합니다.
- 매개변수 키는 이름의 CRC32로 유도하므로, 매개변수를 추가하거나 빼도 나머지 매개변수의 표본이 같습니다. CRC32가 겹치는 이름 쌍은 생성 시 오류입니다.
- `"correlations"`의 관측량 목록은 `"expectations"` 목록 뒤에 2차 관측량을 덧붙인 것이므로, 공통 관측량은 두 모드에서 같은 측정 잡음을 받습니다(공통 난수로, 모드 비교의 분산을 줄임).
- `fold_in`으로 잎과 스텝을 유도하므로 키는 진행한 스텝 수로 결정되고, 재시작과 병렬 실행에서 호출 순서에 의존하지 않습니다.
- 에피소드 키 생성 규칙(고정): 실행 key 하나에서 i번째 에피소드의 key는 `fold_in(run_key, i)`입니다. 벡터 환경과 `qenvs.robust.evaluate`가 이 규칙을 따르므로, 실행 key와 에피소드 번호만 알면 어떤 에피소드든 다시 만들 수 있습니다.
- 상태에는 공칭 `EnvState`에 더해 표본 매개변수와 에피소드 key를 담는 불변 구조를 씁니다(래퍼 전용 상태 클래스). 기존 `EnvState`는 바꾸지 않습니다.
- 보장과 검증의 구분: 결정론적 재현성과 잎 사이의 분리는 테스트로 직접 확인합니다. 통계적 독립성은 증명 대상이 아니며, 표본 분포와 상관 검사는 키 재사용 같은 구현 오류를 잡기 위한 경험적 근거로 취급합니다(6.G2, G7).

### 4.2 모델 매개변수 무작위화: `ParameterRandomization`

```python
from qenvs.wrappers import ParameterRandomization, Normal, TruncatedNormal

renv = ParameterRandomization(
    qenvs.make("transmon/XGate-v0"),
    {
        # 지지집합이 실수 전체: Normal 허용
        "detuning_ghz": Normal(std=0.002, unit="GHz"),
        # 지지집합 (-inf, 0]: Normal은 생성 시 오류, 절단 분포를 씀
        "anharmonicity_ghz": TruncatedNormal(std=0.005, low=-0.02, high=0.02, unit="GHz"),
    },
    strength=1.0,      # 설정 폭(std, half_width)에 곱하는 배율
    oracle=False,      # True: 표본 매개변수를 관측에 붙임(oracle 설정)
)
```

분포와 지지집합
- 모든 분포는 공칭값 기준 오프셋 delta를 뽑고, 매개변수 값은 nominal + delta입니다. 단위는 매개변수의 단위입니다.
- 모델은 매개변수마다 지지집합을 닫힌 구간 [lo, hi]로 선언합니다(끝은 무한대 가능). 예: 트랜스몬 비조화성 (-inf, 0], 결합 세기 [0, inf), 디튜닝 (-inf, inf).

| 분포 | 설정 폭 | strength 적용 | 생성 시 검사 |
|---|---|---|---|
| `Normal(std)` | std | std x strength | 지지집합이 실수 전체가 아니면 오류(`TruncatedNormal`을 안내) |
| `Uniform(half_width)` | half_width | half_width x strength | [nominal - 유효 반폭, nominal + 유효 반폭]이 지지집합 안 |
| `TruncatedNormal(std, low, high)` | std | std만 x strength, low와 high는 그대로 | low <= 0 <= high, low < high, [nominal + low, nominal + high]가 지지집합 안 |

- 순서: (1) 설정 폭에 strength를 곱해 유효 폭을 정하고, (2) 유효 분포가 낼 수 있는 최종 값의 범위가 지지집합 안인지 생성 시 검사하고, (3) 표본을 뽑습니다. 표본을 지지집합으로 자르는 일은 어디에서도 하지 않습니다. 자르면 선언한 분포와 실제 분포가 달라지기 때문입니다.
- strength는 0 이상의 유한값입니다. 유효 폭이 0이면 오프셋은 정확히 0입니다(`TruncatedNormal` 포함).
- `TruncatedNormal`의 low와 high가 비대칭이면 오프셋의 평균이 0이 아닙니다. 분포 객체가 해석적 평균과 표준편차를 제공하고, 문서에 적습니다.

세 가지 폭

| 폭 | 정의 | 쓰임 |
|---|---|---|
| 모델 기준 폭 w_ref | `parameter_specs()`가 선언, 모델 고유 | oracle 정규화 전용, 문서의 권장 규모 |
| 설정 폭 w_cfg | 사용자가 분포에 준 std 또는 half_width | strength = 1일 때의 폭 |
| 유효 폭 w_eff | strength x w_cfg | 실제로 뽑는 분포의 폭 |

- oracle 관측 값은 (표본값 - 공칭값) / w_ref입니다. 사용자 설정과 strength에 무관한 w_ref를 쓰므로, 학습 분포와 평가 분포가 달라도(4.5) 같은 척도로 읽히고 strength = 0에서도 0으로 나누지 않습니다. w_ref가 0이거나 선언되지 않은 매개변수는 oracle 관측에서 뺍니다.

모델 공통 계약(사용자 정의 모델 포함)
- `parameter_specs()`: 무작위화할 수 있는 매개변수마다 단위, 지지집합 [lo, hi], 모델 기준 폭 w_ref를 돌려줌.
- `with_parameters(**values)`: 값을 바꾼 새 모델을 돌려주는 순수 함수(jit과 vmap 안에서 동작).
- `check_parameters(**values)`: 적용 전후의 불변조건 검사(지지집합, 해밀토니안 에르미트성).
- 내장 모델은 해밀토니안 매개변수(디튜닝, 비조화성, 결합 세기, omega0 등)를 선언합니다. 구조 매개변수(`levels`, `n_cells`)와 소산율은 선언하지 않으며, 지정하면 이유와 함께 오류입니다.
- `HamiltonianModel`(사용자 정의 모델)은 이름 붙은 매개변수가 없으므로 매개변수 항으로 지원합니다: `from_operators(..., parameters={"J": (nominal, operator, unit, support, w_ref)})`이면 drift = H0 + sum_k p_k O_k 이고, p_k가 무작위화 대상입니다. 연산자가 에르미트인지는 생성 시 검사합니다.

oracle의 의미
- `oracle=True`는 정책에 실제 표본값을 알려 주는 설정이며, 실제 장비에서는 그 값을 별도 보정으로 추정해야 한다는 점을 문서에 적습니다. 표본은 에피소드 내 고정이므로 `"state"` 관측 모드에서 oracle 관측을 붙이면 관측이 다시 Markov 상태가 됩니다. 블라인드 설정이나 부분 관측 모드에서는 매개변수나 상태의 일부를 모르는 부분 관측(POMDP) 문제입니다.

### 4.3 제어 오차: `ControlErrors`

```python
from qenvs.wrappers import ControlErrors

cenv = ControlErrors(env, amplitude_scale=Normal(std=0.02), step_noise=Normal(std=0.01))
```

- 적용식(고정): 스텝 k, 채널 c에서 u = clip((a (1 + epsilon) + o) (1 + xi_k), -B, B). a는 명령 진폭, epsilon은 상대 배율 오차(에피소드 고정), o는 채널별 절대 오프셋(태스크 단위, 에피소드 고정), xi_k는 스텝별 상대 잡음, B는 `action_bound`입니다. 이것은 명시적으로 정의한 시뮬레이션 모델이며, 모든 장비의 실제 오차 발생 순서를 대표한다고 주장하지 않습니다.
- 지지집합: 상대 오차 epsilon과 xi는 실수 전체를 지지집합으로 둡니다. 4.2의 지지집합은 모델이 유효 범위를 벗어나지 않게 하려는 것인데, 이득 오차는 어떤 실수여도 시뮬레이션이 정의되기 때문입니다(epsilon < -1은 위상 반전). 진폭 한계는 B로 자르는 단계가 담당합니다. 양의 이득을 강제하려면 `TruncatedNormal`을 씁니다.
- 채널 간 상관: 기본은 채널마다 독립 표본, `correlated=True`면 모든 채널에 같은 값(예: 공통 AWG 이득 오차).
- 잡음 뒤 자르기는 분포를 경계에 쌓이게 하므로, 스텝마다 잘린 채널의 비율을 `info["clip_fraction"]`로 보고하고 벤치마크 문서에 함께 적습니다.

### 4.4 측정: 관측 모드와 `shots`

| 모드 | 관측 | shots | 분류 |
|---|---|---|---|
| `"state"` | 상태를 펼친 것과 시간 비율(게이트 태스크는 전파자 또는 초연산자) | 불가 | 이상적 시뮬레이터 기준선, 기본값, 지금과 동일 |
| `"expectations"` | 모델 관측량의 기댓값과 시간 비율 | 가능 | 측정 통계형 부분 관측 |
| `"correlations"` | `"expectations"` 목록 뒤에 2차 상관 관측량(모델이 정의) | 가능 | 측정 통계형 부분 관측 보강 |
| `"time"` | 시간 비율만 | 불가 | 개루프(블라인드) 제어 |

"측정 통계형"은 이상적인 상태 진화에 유한 샷 추정의 잡음만 더한 관측이라는 뜻입니다. 실제 하드웨어 측정 과정(측정 역작용, 판독 오류, 측정 기반 피드백)은 포함하지 않으며, 이 모드의 결과를 하드웨어 실험 환경의 결과로 표현하지 않습니다.

shots 규칙
- `shots=None`(기본)이면 시뮬레이터가 계산한 정확한 기댓값을 그대로 줍니다. 측정 잡음이 없는 이상값입니다.
- `shots`는 양의 정수이고, `"expectations"`와 `"correlations"`에서만 허용합니다. `"state"`나 `"time"`에 `shots`를 주면 생성 시 오류입니다. 적용되지 않는 설정을 조용히 무시하지 않습니다.
- 관측량 목록에 같은 연산자(연산자 노름 차 1e-12 이하)가 두 번 있으면 생성 시 오류입니다. 중복은 샷 비용을 두 번 세게 만들기 때문입니다.

유한 샷 모델
- `shots=n`이면 관측량마다 그 고유기저에서 n번 측정한 결과로 추정합니다. 관측량 O의 서로 다른 고유값 lambda_j와 확률 p_j = Tr(P_j rho)로 결과 횟수를 다항분포에서 뽑고(조건부 이항분포의 연쇄로 정확히 구현, 축퇴 고유값은 한 결과로 묶음), 추정값은 결과 고유값의 표본 평균입니다. 분산은 정확히 (⟨O²⟩ - ⟨O⟩²)/n이고, 사영 연산자의 p(1-p)/n은 그 특수한 경우입니다.
- 관측량마다 별도 실험으로 측정한다고 가정하므로, 서로 교환하지 않는 관측량도 문제없습니다. 실제로는 교환하는 관측량끼리 샷을 공유할 수 있지만 모델링하지 않습니다(비용을 보수적으로 셈).
- 샷 예산: 관측량이 K개면 스텝당 총 측정 횟수는 shots x K입니다. `shots=1000`은 관측량당 1000샷이며, 스텝당 총 샷을 `info["shots_used"]`로 보고합니다. 매 스텝 별도 실험을 반복하는 비용이라는 점도 문서에 적습니다.
- 관측량은 에르미트 연산자여야 하며(결과가 실수 고유값), 비에르미트 연산자는 생성 시 거부합니다. 복소 상관량이 필요하면 실수부와 허수부를 각각 에르미트 관측량으로 정의합니다.
- 관측은 양자 상태를 바꾸지 않습니다(측정 역작용 없음). 결과는 "이상적인 상태 진화에 잡음 있는 관측을 결합한 제어"이며, 측정 결과로 상태가 붕괴하는 폐루프 피드백은 아닙니다.

게이트 태스크
- `"state"`는 단일 상태가 아니라 누적 전파자(닫힌계) 또는 초연산자(개방계)를 반환합니다. 실험에서 이것을 얻으려면 여러 입력 상태와 측정 설정을 쓰는 공정 단층촬영이 필요하므로, 이 모드는 측정 통계형 관측이 아니라 이상적 시뮬레이터 기준선입니다. 환경의 `observation_kind` 속성("state", "propagator", "superoperator")과 문서로 구분합니다.
- 0.3에서 게이트 태스크는 `"state"`와 `"time"`만 지원합니다. `"expectations"`는 어떤 탐침 입력 상태를 진화시켜 무엇을 측정할지 설계가 필요하므로 0.4로 넘깁니다.

정보 경계
1. 정책 입력은 `observation`뿐입니다.
2. 기본 `info`: `"state"` 모드는 지금과 같습니다(릴리스 동작 보존). 부분 관측 모드(`"expectations"`, `"correlations"`, `"time"`)에서는 태스크의 정확값 키(fidelity, leakage, energy, ergotropy)와 정확한 기댓값을 기본 `info`에서 빼고, 비용 정보(`shots_used`, `clip_fraction`)만 남깁니다.
3. `diagnostics=True`(기본 False)면 정확값을 `info["diagnostics"]`에 넣습니다. 평가와 디버깅 용도입니다.
4. 함수형 `env.diagnostics(state)`와 `env.info(state)`는 언제나 정확값을 돌려줍니다. 이 값을 정책 입력에 넣지 않는 것은 API가 막을 수 없고 호출자의 몫이라는 한계를 문서에 적고, 예제는 학습 루프와 평가 코드를 분리합니다.
5. 보상: 관측 모드는 관측만 바꾸고 보상은 바꾸지 않습니다. 보상은 정확한 시뮬레이터 값(스텝별 이득)이므로, 부분 관측 모드에서도 보상의 누적 합으로 성능 지표의 정확한 궤적을 알 수 있습니다. 시뮬레이션 RL의 표준 가정이지만 실험과는 다르다는 점을 문서와 시연 결과에 적습니다. 보상을 측정으로 추정하는 설정은 0.4입니다(8절).

### 4.5 강건성 평가: `qenvs.robust.evaluate`

성능 지표와 보상의 구분
- `episode_return`: 학습용 누적 보상. 현재 태스크는 이득 보상이라 Q(final) - Q(initial) 꼴입니다.
- `performance_metric`: 강건성 평가에 쓰는 물리적 최종 성능. 태스크마다 `TaskSpec`에 키를 선언하고, 최종 상태의 `env.info(state)`에서 읽습니다.

| 태스크 | performance_metric |
|---|---|
| `transmon/XGate-v0`, `transmon/SXGate-v0`, `transmon/CRGate-v0` | `"fidelity"`: 최종 평균 게이트 충실도(누설 반영) |
| `qubit/StateTransfer-v0`, `transfer/LambdaSTIRAP-v0` | `"fidelity"`: 최종 목표 상태 충실도 |
| `battery/TwoLevel-v0`, `battery/Dicke-v0`, `battery/DickeLocal-v0` | `reward` kwarg와 같은 양(`"energy"` 기본, 또는 `"ergotropy"`)의 최종값 |

- 인터페이스: `evaluate(env, policy, key, n=1024, metric=None, distribution=None)`. `metric`의 기본값은 태스크 선언이며, 다른 info 키나 (state) -> 스칼라 함수로 바꿀 수 있습니다. `episode_return`은 별도 열로 함께 보고하되 집계 기준은 `metric`입니다. `policy`는 개루프 펄스 배열 (H, A) 또는 (관측, key) -> 행동 함수이며, 확률적 정책은 시점 t마다 `fold_in(fold_in(episode_key, 3), t)`를 key로 받습니다(4.1의 잎 3).

통계
- 보고: 평균, 최솟값, 하위 10% CVaR. CVaR 추정량은 n개를 정렬해 하위 k = ceil(0.1 n)개의 평균이며, 성능 기준 정의라 손실 기준 CVaR와 꼬리 방향이 반대라는 점을 문서에 적습니다. 이 추정량은 O(1/n)의 편향이 있습니다(균등 U(0, 1)에서 기댓값이 정확히 (k+1)/(2(n+1)), 모집단 값은 0.05).
- 최솟값은 표본 수가 늘수록 낮아지는 기술 통계로만 보고하고, 표본 수가 다른 최솟값끼리 비교하지 않습니다.
- 구간: 비모수 백분위 부트스트랩. 에피소드 단위 지표 n개를 복원추출하고, B = 2000, 2.5와 97.5 백분위입니다. 평가 key에서 에피소드 루트 `fold_in(key, 0)`과 부트스트랩 key `fold_in(key, 1)`을 따로 유도합니다.
- 구간 제공 범위(사전 몬테카를로로 결정, 각 조건 독립 반복 1000회): n = 1024에서 포함률은 평균 구간 0.943, 0.952, CVaR 구간 0.944, 0.946(균등 분포, 충실도형 분포)으로 명목 0.95와 맞았습니다. n = 256에서는 CVaR 구간이 충실도형 분포에서 0.912로 부족했습니다. 그래서 평균 구간은 n >= 256, CVaR 구간은 n >= 1024에서만 제공하고, 그보다 작은 n에서는 CVaR 점추정만 경고와 함께 보고합니다. 이 n >= 1024는 검증한 두 분포에서 CVaR 구간을 제공하기 위한 최소 조건이며, 임의의 성능 분포에서 명목 95% 포함률을 보장한다는 뜻이 아닙니다. 백분위 부트스트랩은 꼬리 통계량에서 분포에 따라 성질이 달라지므로, 꼬리가 두껍거나 이산적이거나 경계에 질량이 몰린 분포(예: 상한 1에 몰린 충실도)는 별도 검증 대상으로 문서에 적습니다.
- 기본 평가 표본 수 1024. 256, 1024, 4096에서 평균과 CVaR이 안정적인지 보고합니다. 무작위화가 없는 공칭 환경의 성능도 함께 보고해, 강건성을 얻느라 공칭 성능을 잃었는지 보이게 합니다.
- 학습과 평가 분리: `evaluate`는 명시적 평가 key를 요구하고, 평가 분포를 따로 받을 수 있습니다. 학습에 쓴 key 스트림과 겹치지 않도록 문서와 예제에서 분리합니다.
- 학습 결과 비교는 여러 독립 학습 시드로 하고, 학습 시드 간 변동(정책마다 다름)과 평가 표본 변동(분포에서 다시 뽑을 때)을 하나의 구간으로 합치지 않고 따로 보고합니다.

## 5. 호환성

- 새 래퍼와 kwargs(`observation`, `shots`, `diagnostics`)는 추가뿐이고, 기본값은 지금 동작과 같으므로 릴리스된 태스크 id는 그대로 둡니다(스냅샷 테스트로 확인). 부분 관측 모드의 info 변경은 새 모드에만 적용됩니다. 공개 API는 추가만 합니다(API 게이트).
- 기존 `EnvState`와 `step`은 바꾸지 않습니다. 스텝별 난수는 래퍼와 관측 계층에서 `fold_in`으로 유도하므로 기존 태스크의 key 처리도 그대로입니다.

## 6. 검증 게이트 (통과 못 하면 해당 항목은 0.3에서 제외)

공통 규칙: 통계 게이트는 테스트마다 고정한 key를 써서 판정이 결정론적이고, 허용 기준은 구현 전에 이 문서에 고정합니다. 모든 통계 게이트 앞에 결정론적 기준값 테스트를 둡니다. 통계 검사는 약 20개이고 각각 4 SE(정규 근사 양측 6.3e-5)이므로, 정상 구현이 우연히 떨어질 확률은 합쳐서 약 1e-3입니다.

- **G1 기본 동작 보존**: 측정 잡음과 스텝별 제어 잡음이 꺼져 있고 모든 폭이 0이면, 래퍼를 씌운 환경의 전이, 보상, 관측이 원래 환경과 x64에서 값이 같다(모든 태스크). 비교는 IEEE 값 비교(`np.array_equal`, -0.0과 +0.0은 같음).
- **G2 재현성과 분리**:
  - 같은 key와 설정이면 모든 출력의 값이 같다(x64, float32).
  - 배치 위치 독립: 단일 실행과 1024개 배치 실행에서 같은 에피소드 key의 난수 표본(매개변수, 보정 오차, 스텝 잡음)은 값이 같고, 시뮬레이션 결과(관측, 보상)는 x64에서 1e-12 이내다(배치 실행은 XLA 연산 순서가 달라 마지막 비트가 다를 수 있음). 샷 계수는 같은 확률을 입력한 단위 테스트에서 값이 같다.
  - 잎 분리: 한 잎의 설정(분포, 폭, 켜고 끔, `correlated`, `shots`, 관측량 수)을 바꿔도 다른 잎의 표본이 같다. 매개변수를 추가해도 기존 매개변수의 표본이 같다. `"expectations"`와 `"correlations"`에서 공통 관측량의 샷 결과가 같다.
  - 에피소드 키 규칙 `fold_in(run_key, i)`로 임의의 에피소드를 재생성할 수 있다.
  - 정책 키: 같은 에피소드의 서로 다른 시점이 같은 정책 키를 받지 않고(키 구조 검사), 같은 key로 돌린 확률적 정책의 행동 열이 값까지 같으며, 정책 난수를 쓰거나 안 써도 다른 잎의 표본이 같다.
  - 경험적 검사: 1024개 에피소드 표본의 평균과 분산이 선언한 분포와 4 SE 이내, 인접 에피소드 간과 잎 간 상관계수가 |r| <= 4/sqrt(n). 이것은 독립성의 증명이 아니라 키 재사용 같은 구현 오류를 잡는 검사다. "서로 다른 key는 서로 다른 값"은 요구하지 않는다.
- **G3 물리 제약과 분포 규칙**:
  - 생성 시 오류: 지지집합이 실수 전체가 아닌 매개변수에 `Normal`, 유효 범위가 지지집합을 넘는 `Uniform`, low > 0 또는 high < 0 또는 low >= high 또는 범위가 지지집합을 넘는 `TruncatedNormal`, 음수나 무한대 strength.
  - 4096개 표본 전부가 [nominal + low, nominal + high]와 지지집합 안에 있다. 유효 폭 0이면 오프셋이 정확히 0이다.
  - 비대칭 `TruncatedNormal`의 표본 평균과 표준편차가 해석값과 4 SE 이내다.
  - 표본마다 해밀토니안이 에르미트다.
- **G3b 모델 계약**: 모든 내장 모델과 매개변수 항을 쓴 `HamiltonianModel`에서 `with_parameters`가 jit과 vmap 안에서 동작하고, `check_parameters`가 지지집합 밖의 값과 비에르미트 결과를 거부한다.
- **G4 해석 검증**:
  - 가정: 상대 진폭 오차 epsilon, 평균 0, 에피소드 고정, 2준위 극한의 닫힌 공진 pi 펄스. 펄스는 일정 진폭 a = pi / T를 I 채널에만 주고 Q 채널은 0이다. 트랜스몬의 구동항 (Omega_I / 2)(a + a^dag)는 2준위에서 (Omega / 2) sigma_x이고, 큐비트는 H = (Delta / 2) sigma_z + u sigma_x / 2에서 Delta = 0이므로, 두 경우 모두 회전각은 진폭 x 시간이다.
  - 사전조건(결정론, x64, 모두 통과해야 통계 단계로 감):
    - P1 설정 확인: `levels=2`, 디튜닝 0, T1과 T2 또는 감쇠율 없음(닫힌계 경로), Q 채널 0, 검사 대상이 아닌 오차원은 모두 꺼짐.
    - P2 epsilon = 0에서 1 - F <= 1e-12(진폭과 시간의 단위, 정규화가 회전각 pi와 맞음).
    - P3 epsilon을 0.01, 0.1, 0.3으로 고정하면 1 - F_avg와 1 - F_state가 아래 닫힌 형식과 1e-10 이내. 스텝 잡음은 고정한 xi 벡터에서 회전각 pi (1 + mean(xi))의 닫힌 형식과 1e-10 이내.
    - P4 통계 단계의 모든 표본에서 `clip_fraction`이 0(자르기가 공식을 깨지 않음). 트랜스몬 기본값(32 ns, 상한 50 MHz)에서 a = 0.098 rad/ns, 상한 0.314 rad/ns이므로 sigma = 0.2의 5 sigma 표본(진폭 2배)도 잘리지 않는다.
  - 닫힌 형식: 회전각 pi (1 + epsilon)에서 1 - F_avg = (2/3) sin²(pi epsilon / 2), 상태 불충실도(|0>에서 |1>)는 1 - F_state = sin²(pi epsilon / 2). 기댓값은 근사 없이
    - 정규 N(0, sigma²), sigma는 표준편차: E[1 - F_avg] = (1/3)(1 - exp(-pi² sigma² / 2)), E[1 - F_state] = (1/2)(1 - exp(-pi² sigma² / 2))
    - 균등 U(-a, a), a는 반폭(표준편차 a/sqrt(3)): E[1 - F_avg] = (1/3)(1 - sin(pi a)/(pi a)), a = 0에서는 극한값 0
    - 스텝별 잡음은 적용 범위를 한정한다: 일정 진폭 pi 펄스를 H개의 같은 스텝으로 나누고 각 스텝에 독립 상대 잡음(표준편차 s)만 있을 때, 회전축이 같으므로 회전각 오차는 pi 곱하기 평균 잡음이고 표준편차는 s/sqrt(H)다. 이 경우에만 정규 공식에 sigma 대신 s/sqrt(H)를 넣어 검증하고, 진폭이 스텝마다 다른 일반 궤적에는 이 공식을 주장하지 않는다.
  - 통계: `transmon/XGate-v0`(`levels=2`)와 `qubit/StateTransfer-v0`에서 4096개 표본의 평균이 표본 표준오차의 4배 이내. 이 식들은 몬테카를로로 미리 확인했다(sigma = 0.01, 0.05, 0.2와 a = 0.02, 0.1, 0.3에서 상대 오차 0.1% 이내).
- **G5 측정 통계**:
  - 설정 검사: `shots`와 `"state"` 또는 `"time"`의 조합, 양의 정수가 아닌 `shots`, 비에르미트 관측량, 중복 관측량을 생성 시 거부한다.
  - 결정론: `shots=None`이면 정확값과 같다. 분산이 0인 경우(상태가 관측량의 고유상태, 또는 사영 연산자에서 p가 0이나 1)는 모든 반복에서 해당 결과의 계수가 정확히 n이고 추정값이 고유값과 1e-12 이내다(x64). 관측 전후의 양자 상태가 같다.
  - 통계(반복 R = 10^4, 고정 key; 사례는 사영 연산자 p = 0.3, 드문 사건 p = 1e-3, Dicke N = 4 에너지(고유값 5개), 축퇴 고유값이 있는 관측량; n은 100과 1000):
    - 결과별 빈도: 각 결과의 평균 빈도가 p_j와 4 sqrt(p_j (1 - p_j) / (n R)) 이내.
    - 평균: |평균 - ⟨O⟩| <= 4 sqrt(v / R), v = (⟨O²⟩ - ⟨O⟩²) / n.
    - 분산: |s² - v| <= 4 SE_v, SE_v = sqrt((m4 - (R - 3)/(R - 1) v²) / R), m4 = mu4 / n³ + 3 (n - 1) sigma⁴ / n³. 여기서 sigma²와 mu4는 단일 샷 결과 분포의 정확한 2차, 4차 중심모멘트이고, m4는 추정값의 4차 중심모멘트다. 상대 기준을 쓰지 않으므로 작은 분산에서도 척도가 자동으로 맞는다.
    - 사전 몬테카를로(사례마다 20회): 표준화 편차의 표준편차 0.77에서 1.30, 평균 절댓값 0.36 이하로 공식이 맞았다. 참고로 이전 판의 상대 5% 기준은 흔한 경우 약 3.5 SE, p = 1e-3과 n = 100에서는 약 1.4 SE에 해당했다.
    - 스텝 간 독립: 같은 에피소드의 스텝 t와 t+1 추정값의 상관이 |r| <= 4/sqrt(R).
  - 정보 경계: `diagnostics=False`(기본)에서 부분 관측 모드의 관측과 `info` 어디에도 정확값이 없다(키 검사). `"state"` 모드의 `info`는 지금과 같다(스냅샷). `info["shots_used"]`가 shots x 관측량 수와 같다.
- **G6 강건성 평가**:
  - G6a 추정량. 결정론 먼저: 손으로 계산한 배열(동점 포함)에서 평균, 최솟값, CVaR이 정확히 일치하고, 무작위화가 없는 환경에서 `evaluate`의 metric이 최종 `env.info(state)`의 해당 값과 같으며 `episode_return`과 따로 보고된다. 통계: 균등 U(0, 1) 성능에서 반복 2000회의 CVaR 추정량 평균이 정확한 유한 표본 기댓값 (k+1)/(2(n+1))과 4 SE 이내(n = 256, 1024, 4096; 사전 확인에서 일치).
  - G6b 구간 포함률: n = 1024, B = 2000, 고정 key의 독립 반복 1000회, 분포 2개(균등 U(0, 1); 충실도형 F = 1 - (2/3) sin²(pi epsilon / 2), epsilon ~ N(0, 0.05²), 참값은 수치적분). 평균 구간과 CVaR 구간의 포함률이 [0.92, 0.98] 안(0.95에서 이항 표준오차 0.0069의 약 4배). 사전 확인 0.943에서 0.952. 이 게이트가 보이는 것은 두 분포에서의 포함률이며, 다른 분포에 대한 보장으로 일반화하지 않는다(4.5).
  - G6c 사용 규칙: 평가 key를 주지 않으면 오류. n < 1024에서는 CVaR 구간 대신 경고와 점추정. 256, 1024, 4096 표본에서 평균과 CVaR의 변화를 보고(최솟값은 기술 통계로만).
- **G7 배치 실행**: 1024개 에피소드에서 잎 간과 에피소드 간 상관을 G2와 같은 경험적 기준으로 검사하고, 시간과 메모리 사용을 측정해 문서에 기록.

## 7. 시연 (게이트 아님, 결과를 있는 그대로 공개)

- Dicke 배터리 N=4에서 PPO를 관측 조건 3가지(`state`, `expectations`, `expectations`와 1000샷)로 3시드씩 학습하고, 별도 평가 key로 평가. 세 조건 모두 같은 정확값 보상을 쓴다는 점(4.4 정보 경계 5)을 결과와 함께 적습니다.
- 트랜스몬 X 게이트에서 공칭 GRAPE와 강건 GRAPE(학습 표본 K개 평균 최적화)를 진폭 오차 분포 위에서 평균, 최솟값, CVaR로 비교(평가 표본은 학습 표본과 분리, n = 1024 이상).
- 같은 평가 분포에서 블라인드 정책과 oracle 정책 비교.

## 8. 범위 밖과 향후 설계 메모

- 소산율 무작위화: 현재 소산율이 0인지 아닌지가 닫힌계와 개방계 경로, 상태 종류(ket과 밀도행렬)를 정합니다. 무작위화하려면 "항상 개방계 경로" 옵션(rate 0도 점프 연산자로 포함)이 필요하고, 이것은 기존 태스크의 경로를 바꾸므로 새 태스크 id나 옵션으로 설계해야 합니다.
- 구조 매개변수(`levels`, `n_cells`, Fock 컷오프): 배열 크기가 바뀌므로 jit과 vmap 안에서 무작위화할 수 없습니다. 크기별로 따로 컴파일하는 방식이 필요합니다.
- 게이트 태스크의 `"expectations"`: 탐침 입력 상태 집합과 측정 관측량의 설계가 필요합니다.
- 보상의 측정 추정: 유한 샷으로 추정한 보상, 종단 보상만 주는 설정.
- 교환하는 관측량의 샷 공유.
- 측정 역작용, 확률 주 방정식, 단일 샷 판독, 측정 기반 피드백: dynamiqs의 SME 솔버를 이용한 별도 기능으로 계획합니다.

## 9. 핵심 기여 (문서와 릴리스 노트의 표현)

1. 재현 가능한 물리 매개변수 무작위화: 잎 단위로 고정한 난수 구조, 에피소드 고정 표본, 배치 실행.
2. 관측 불확실성의 분리: 이상적 상태와 기댓값, 유한 샷 추정을 구별해 제공.
3. 분포 기반 강건성 평가: 학습에 쓰지 않은 매개변수 분포에서 물리적 최종 성능의 평균과 하위 꼬리를 검증된 구간과 함께 보고.

## 10. 일정과 비용

0.3 계획의 단계 B2로, 진행 중인 단계 B, C, D 이후 rc1 전에 넣습니다. 구현 2개(무작위화와 제어 오차, 관측과 측정 통계와 평가), 적대검증 2개(물리와 통계, API와 변이 테스트)로 에이전트 약 4개, 수정에 1~2개를 더 씁니다. 게이트를 못 넘는 항목은 0.4로 미루고 0.3 일정은 늘리지 않습니다.

## 11. 위험

- 매 스텝 `eqx.tree_at`으로 모델을 바꾸는 비용: 처리량 저하를 측정해 문서에 적습니다.
- 고유분해가 필요한 관측량의 측정 모델: 고유분해는 모델 생성 시 한 번만 하고, 축퇴 고유값은 같은 결과로 묶습니다.
- G6b의 포함률 검사는 반복 1000회 x B 2000 x n 1024라 무겁습니다(사전 확인에서 numpy로 분포당 약 30초). 느린 테스트 표식으로 분리해 CI의 한 잡에서만 돌립니다.
- 기댓값 관측이 실험적으로 얼마나 비싼지(관측량당 n샷, 매 스텝)는 사용자 판단 몫이며 문서에 명시합니다.

## 12. 상태

3차 검토의 P0 3건과 P1 7건, 리드가 추가로 찾은 2건, 4차 검토의 P0 1건과 P1 2건을 반영했습니다. 수치 기준(G5의 분산 표준오차, G6의 포함률 허용 범위와 구간 제공 최소 n)은 구현 전에 몬테카를로로 확인해 고정했습니다. 남은 설계 결정은 없고, 구현 착수를 기다립니다. G1에서 G7과 G3b를 순서대로 진행하며, 게이트를 통과하지 못한 기능은 성능과 무관하게 0.3에 넣지 않고 0.4로 넘깁니다.
